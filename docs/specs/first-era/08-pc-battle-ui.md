# 継世の戦闘 — 第一紀 PC戦闘UI改修仕様（Codex引き継ぎ用）

- 作成日：2026-11-06
- 対象：`elizabeeeth555/roguelike-card-game` の第一紀ブラウザ版
- 状態：ユーザーが画面全体モックの方向性を承認済み。演出の詳細数値など一部は暫定。
- 目的：**PC戦闘画面の視認性・操作性・ボスの存在感を向上**させる。カードゲームとしての情報を一画面に収める。

> **重要：これはUI改修仕様であり、戦闘バランス・カード性能・毒ダメージの処理時点・敵AIの正式変更を承認するものではない。** 別途Codexでルール比較検証が進行中のため、その検証コードや差分を上書き・取り込まない。作業時の実際のブランチと差分を最初に確認すること。

## 0. Codexに依頼する作業と制約

1. 本書と現行実装・既存設計資料の整合を確認し、UIを改修する。実装しきれない点や仕様矛盾がある場合は、重要点を報告し、独断でルールを変更しない。
2. 原則としてHTML/CSS/UIレンダリング・UIイベント・アニメーションを編集する。戦闘ロジックの変更は**UI表示のためにどうしても必要なインターフェース調整のみ**とし、勝敗・効果・CD・カード性能・AIの判断を変えない。
3. 既存のカード19種、3ビルド、5ボス、BGM/SE、結果画面、リトライ、保存済み画像の使用可否を維持する。
4. 途中のユーザー承認を待つ必要がある仕様変更や、ルール比較検証中の設定値への変更は行わない。
5. **自動コミット・プッシュ・デプロイは禁止。** ローカルで修正・テストして、差分と検証結果を報告する。必要ならUI専用ブランチを提案してよいが、無断で共有ブランチを更新しない。
6. PC画面を主対象としつつ、スマホ版の既存の操作可能性を壊さない。既存のテストコマンドを実行し、必要なUIテストを追加する。

## 1. 画面構成・レイアウト（承認済み）

### 1.1 PC全体

- **PC戦闘画面は原則スクロールなしで一画面に収める。** 目安として `1366×768`、可能なら `1280×720` の表示領域でも主要操作が常時見えることを確認する。
- 大きな**ボスの立ち絵を戦闘フィールド中央**に表示する。主人公の後ろ姿の大きな立ち絵は戦闘画面から外す。
- ゲーム画面上部には既存の設定操作（通常／高速、音量など）を維持する。
- **戦闘フィールドの最上部に横幅の広いボス専用HUD**を置く（ページ全体とは別の独立ヘッダーにしない）。ボス名、横長HPバーと数値、MP、発生中の状態、仮の固有能力アイコンを表示する。
- **ボスHUDの直下に敵デッキ5枚をミニカードで横並び常時表示**する。5枚とも中身を公開し、使用順の予告は行わない。ボスの大きさを著しく損なう場合はカードの余白や寸法を先に圧縮する。
- 戦闘フィールド左下に**プレイヤー用のコンパクトHUD**を配置する。顔アイコン、名前、HPバーと数値、現在MP／上限、状態異常・バフのアイコンを表示する。
- プレイヤーの手札は画面下部に通常5枚と将来用の継承専用1枠を横並びに配置。継承枠は今は未解放／予約表示のみ。
- **手札の右に、上から「マナ加速」「ターン終了」ボタンを縦配置**する。
- 戦闘ログは常設パネルとして画面中央を占有しない。**ログボタンで右側から展開するドロワー**にする。開いても戦闘やアニメーションを停止せず、ログがリアルタイム追加される。ユーザーが古いログを読んでいる場合は自動スクロールで位置を奪わない。
- すべての情報パネルは画面・立ち絵を圧迫しないよう、必要なら半透明とする。小さすぎる文字で帳尻を合わせない。
- ユーザー承認済みの画面モックは**見た目の方向性の参考**。モック内のカード名・HP・効果などの仮データは正式な仕様ではない。実装の真値は現行ゲーム状態を優先する。

### 1.2 HUDの状態表示

- 状態異常・バフは**発生中のものだけ**表示。値が0のアイコンは隠す。
- **数値はアイコンの内側に重ねる**（盾4なら盾アイコン内に「4」）。数値をアイコンの横へ重複表示しない。
- HPが少なくなった際、HPバーの色変化や顔アイコンの枠などで危機状態を表現する（具体的な閾値・点滅速度は後述の暫定事項）。
- マナの現在値／上限はプレイヤーHUDで常時確認できる。加速予約中なら予約状態もわかるようにする。
- 発生中の効果は、ホバーやクリック／タップで説明を確認できるようにする。
- ボス用HUDにも同様の状態アイコン表示ルールを適用する。
- プレイヤー自身の大きな立ち絵は戦闘には不要。主人公の個性はHUDの顔アイコン、および**将来の道中立ち絵・アニメーション**で表現する。道中演出の新規実装は今回の範囲外。

## 2. 敵味方のカード表示（承認済み）

### 2.1 カードに常時表示する内容

- カード名・消費MP・カード種別・効果の短い要約・**基本CD**を表示する。
- 基本CDは**カード下部**に常時配置する。例：`1MP / 基本CD1`。CD0も含め、実際の定義値に基づく。
- 表示が窮屈であれば効果の短い要約をカード本体から省き、カード名・コスト・アイコンを残す簡略案に切り替える候補。ただし**自動的に正式変更せず、見た目を比較して報告**する。
- どのカードもクリック／タップで効果全文と発動条件を確認できる。敵デッキも同じ方式。敵カードには使用ボタンを出さない。
- 敵デッキはミニカード、プレイヤーの手札はより大きなカードとして表示してよい。状態の意味と見た目のルールは敵味方で共通にする。

### 2.2 使用済・クールダウン・使用不可の表示

以下は**基本性能**と**現在状態**を混同しない。

| 状況 | 見た目・表示場所 | 補足 |
|---|---|---|
| 通常／CD制限なし | カード本来の色と明るさ | 実際の使用可否はマナ・条件も考慮 |
| その自ターンで使用済 | カード全体を暗くし、中央に「使用済」表示 | 同時にCD中なら両方表示 |
| クールダウン中 | カードを暗くし、**右上に小さな残りCDバッジ** | `基本CD1` とは視覚的・文言的に明確に分離。例：`残1` |
| マナ不足 | コスト表示を赤くする | 使用済／CDと同一の理由表現にしない |
| 発動条件未達 | 条件未達マークを付ける | 詳細で理由を表示 |

- 使用済・CD中は独立した状態である。どちらも該当するなら**「使用済」＋「残りCD」**を同時に表示する。
- 残りCDは**所有者の自ターン基準**で表示する。CD1は「使用した次の自ターンは使用不可、その次の自ターンに再使用可能」という現行ルールを厳守する。
- ユーザー意図：残りCDの更新タイミングは**カード所有者のターン開始時**を基準とする。ただし、内部のカウンタが0になった瞬間に誤って解禁されるような表示にせず、**実際の使用可否と『次に使用可能になる自ターン』を真値として**表示を設計する。必要なら`残1`の意味を「今後使用不可の自ターン数（今ターンを含む）」などに厳密化し、テストで確認する。
- カード使用・ターン切替・CD更新・状態変化のたびに**リアルタイム更新**する。敵デッキも画面に表示したまま更新する。
- 原則として敵の「使用済」は**その敵自身のターン中**に表示し、その後のプレイヤーターンでは使用済マークは消してCDなど継続する状態のみ表示する。プレイヤー側も対称的に扱う。
- グレーアウトしても、名称・基本CD・残りCDが読めるコントラストを確保する。色以外に文字とアイコンでも区別する。
- **カードを使えるかの判定は現行エンジンを優先**し、表示都合で可否を変更しない。

### 2.3 カード詳細・選択操作

- **自分のカード：クリック／タップで選択すると、そのカード自身が画面手前に浮き上がるように拡大**。隣のカードを押し広げたり、画面全体を再配置したりしない。
- 選択した自分のカードの**すぐ下に「使用する」ボタン**を表示。使用可能な場合のみ実行できる。
- カード外の余白をクリック／タップすると選択解除。別の自分のカードを選ぶと選択先が切り替わる。
- 使用すると選択は自動解除し、拡大表示を閉じる。使用済／CDの見た目へ更新する。
- 敵カードもクリック／タップで拡大。こちらは効果確認専用で使用ボタンはない。
- **プレイヤーターン中は敵カード最大1枚＋自カード最大1枚を同時に拡大可能**。どちらも周囲を押し広げず、画面を自動調整して互いに重ならないようにする。
- **敵ターン中はカードの拡大・選択操作を禁止**。敵ターン開始時に開いていたカード詳細は閉じる（ただし敵デッキの常時表示、CD・使用済のリアルタイム更新は続ける）。
- 将来の妨害カードによる敵ターン中の応答UIは未設計につき、今は例外処理を追加しない。

## 3. 操作・予測表示（承認済み）

### 3.1 ダメージ予測

- 自分の攻撃カードを選択した際、**ボスHPバー付近に予測ダメージを可視化**。可能ならHPバーの予測減少領域を重ねる。
- 計算にはカードの条件、現在の攻撃バフ／弱体、ボスのバリアなど、現行の戦闘ルール上その時点で確定している要素を反映する。
- **HPへのダメージとバリア消費を混同しない**。条件未達の攻撃などは詳細画面で理由もわかるようにする。
- 予測は情報表示のみ。カード選択によって戦闘状態を変更しない。相手の未来の行動は予告しない。

### 3.2 カード使用、演出中操作

- **カード選択 → 使用ボタン**の2段階操作。PC／スマホで共通。スマホのスワイプ使用は将来の候補、今回実装しない。
- **自分のカード演出中も、次カードの選択・詳細確認は可能**。ただし、使用ボタン・マナ加速・ターン終了などの戦闘状態を変更する操作は演出終了まで実行不可。
- 効果処理は順次直列化し、演出中のダブルクリックや選択変更で重複適用されないこと。
- キーボードショートカットがある場合も、使用・ターン終了に関するロックや確認条件を必ず通す。

### 3.3 マナ加速・ターン終了

- マナ加速は**確認なしで即実行**。2MP消費、次の自ターンから上限＋1（最大5）という現行仕様のまま。
- ターン終了は手札右側の操作列の下側ボタン。
- **未使用で実行可能なカードやマナが残っている場合だけ**ターン終了確認を表示する。確認時は残MP・実行可能なカードの有無などを伝える。何もできない場合は確認なしで終了。条件の厳密化は実装で既存エンジンの使用可否に合わせ、むやみに毎回確認を出さない。
- ターン終了確認はマウスクリック・キーボードSpaceの両経路に適用。敵ターンや演出中に多重起動しない。

## 4. 戦闘演出・結果（承認済み／秒数は暫定）

### 4.1 カード使用・ダメージ

- **敵味方ともカードはその場で発光して、カード種別に応じたエフェクトを発動**。カードが飛ぶ／画面中央へ移動する演出は今は実装しない。
- カテゴリごとに攻撃／防御／毒／回復／強化・補助などを視覚的に区別する。敵の演出は可能な範囲で中央のボス立ち絵と連動させる。
- 敵が複数枚使うときは**1枚の演出・数値更新を完了してから次のカードへ**。演出同士を重ねない。高速モードでも順序は同じ。
- バリアとHPの双方にダメージがある場合、**盾アイコンとHPアイコンの数値を同時表示**（例：バリア−3／HP−2）。毒のようにHPを直接減らす場合は実際に変動した情報のみ示す。
- 敵デッキは対応する使用カードの発光・使用済への更新が見えること。ログ・HP・状態表示は演出と意味が食い違わないタイミングで更新する。
- 演出時間の仮目安：**通常1枚あたり1.5〜2秒、高速0.6〜0.8秒**。実際のプレイで調整し、テンポ・情報把握を優先する。

### 4.2 ターン演出

- 既存の画面中央のターン切り替え演出を維持する。
- **通常モードの表示時間を現行実装より約0.5秒短縮**する。2026-11-06時点の`src/app/battle-controller.js`では通常`3000ms`、高速`450ms`だったため、実装時に同じなら通常約`2500ms`とする。高速は当面現状維持。
- 敵ターン中のカード詳細選択は禁止。敵の行動・数値表示は引き続きリアルタイムで観察できる。

### 4.3 勝利・敗北

- 別画面へ即遷移させず、**戦闘フィールド（ボスの立ち絵）を背景に残し、中央に大きくVICTORY／DEFEAT**を重ねる。
- 現行の「同じ条件で再戦」「最初から」の導線は維持する。

## 5. デッキ構築画面（承認済み）

- 初期ビルド選択の後、カード獲得の候補**3枚を大きく横並び**に表示する（PC）。
- 各カードの効果を比較でき、1枚を選んでから**獲得ボタンで確定**する。
- 3択×3回、合計通常5枚という既存ルールは変更しない。
- 画面幅が狭い場合は崩れないようレスポンシブに調整。抽選ロジック、候補数、カード内容は変更しない。

## 6. 暫定事項・今回の実装対象外

### 暫定（まず試作し、見た目で再判断）

- カード要約は常時表示を第一候補。窮屈ならアイコン・カード名・コストだけにする案と比較する。
- エフェクトの種類、強さ、再生秒数、低HP時の警告演出（色・閾値・点滅など）。
- ミニカードやボスの実寸。**ボスの迫力と一画面完結を優先**して調整し、読みづらい文字に逃げない。
- スマホ版は「タップで選択 → 使用ボタン」の現行方針を維持。スワイプ操作は後日検討。

### 今回は変更しない

- 毒のターン開始時／終了時の正式ルール、結界・堅守のCDやカード性能、AI探索・評価式、マナ・バリア・HP・勝敗ルール。これらは別途バランス検証中。
- 新しい継承カード、第二紀以降、ボス固有能力、プレイヤーパッシブの実装（予約表示のみ）。
- 敵ターン中の妨害カードの選択UI（現時点で対象カードの設計が未確定）。
- 道中での主人公全身立ち絵／アニメーションの新規制作。
- ボス5種類の個別勝率を均等にするバランス調整。

## 8. 実装の受け入れ条件・テスト

1. PCの `1366×768`、可能なら `1280×720` で、敵HUD・敵5枚・大きなボス・プレイヤーHUD・手札5枚＋継承枠・操作ボタンがスクロール不要で操作できる。
2. 中央のボスが主役。戦闘中の主人公背面立ち絵を非表示にし、顔アイコンだけをHUDに残す。大男・斥候など使用不可と指定された画像を勝手に復活させない。
3. 敵の5枚が常時公開され、カードの使用・CD・使用可能への復帰がリアルタイムに反映。**基本CDと残りCDが混同されない**。
4. **CD1：使用ターンは使用済＋残り表示 → 次の自ターン使用不可 → 次々自ターン使用可能**。CD0、CD2、複数カード使用でも正しい。プレイヤー・ボス双方同じ。
5. 敵味方カードは自ターン中に個別拡大可能。プレイヤーターン中は敵・自分各1枚を同時に拡大でき、互いに重ならない。敵ターンには詳細操作不能。
6. 使用済／CD中は暗転、マナ不足は赤いコスト、条件未達は専用マーク。カードを開けば理由を確認できる。
7. プレイヤーがカードを選ぶと、ボスHPバーに実際のルールに沿った**確定HPダメージ予測**を表示。バリア消費をHP減少として表示しない。選択だけでは状態を変更しない。
8. 使用は選択後の「使用する」で確定。カード外クリック解除、使用後自動解除。演出中は次カードの選択・詳細確認を許可し、追加の効果実行は禁止。
9. カード使用演出はその場で発光し、カテゴリ別のエフェクトを再生。敵の連続使用は1枚ずつ順序を守る。バリア・HPダメージが同時なら別アイコンで同時表示。
10. ログは右ドロワー、展開中も戦闘は進行。履歴閲覧中に自動スクロールで位置を奪わない。
11. マナ加速は確認不要。ターン終了は必要時だけ確認。キーボード経由も同じ確認・使用禁止条件を守る。
12. 勝敗は戦場上に大きくオーバーレイ表示。再戦・最初からは引き続き機能する。ドラフト3択が大きく並び、獲得確認ができる。
13. 既存のブラウザテストでPC・スマホが崩れず、バトル・カード獲得・勝敗・再戦が動く。
14. `npm test`、`npm run check`、可能なら`npm run test:browser` を実行し、実行結果・失敗項目・スクリーンショットを報告。必要なテストを追加する。

## 9. Codexの報告形式

- 変更ファイルと変更理由。
- PC全体スクリーンショット（少なくとも1366×768）および、カード拡大中・敵CD中・ログ開放中の状態のスクリーンショット。
