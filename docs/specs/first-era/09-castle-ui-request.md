## 1. 画像の受け渡しと取り扱い

### 1.1 ユーザー提供マスター：キャラクター6人

ユーザー提供の正規マスター画像を、以下のキャラクターIDに対応付ける。実際のファイル名が違う場合はマッピングを作成し、**人物を取り違えない**こと。

| キャラクター | IDの例 | 用途 |
|---|---|---|
| 黒剣士 | `01_black_swordsman` | プレイヤー/将来ボス用立ち絵、プレイヤーHUD |
| 重装騎士 | `02_heavy_knight` | ボス立ち絵、顔素材 |
| 魔女 | `03_witch` | ボス立ち絵、顔素材 |
| 大男 | `04_giant_warrior` | ボス立ち絵、顔素材 |
| 斥候 | `05_scout` | ボス立ち絵、顔素材 |
| 賢者 | `06_sage` | ボス立ち絵、顔素材 |

既存の `assets/asset-map.js`、カード/ボスの紐付けと画像読み込み方法を確認して合わせること。従来素材で大男・斥候を非表示にした過去の措置は**旧画像への措置**であり、今回は**ユーザー提供の新マスターが存在して品質確認できた場合**に限り新素材を採用する。紐付けやゲーム進行は変えない。

**画像マスターに必要な検証**：各キャラ1人、前向き・斜め向きの全身像、解像度、縦横比、アルファ透過、背景残り、輪郭品質、顔/指/装備の欠け。PNGにアルファがあっても、透過が完全とは限らない。市松模様や暗色背景が画素に焼き込まれていたら、透過成功と判断しない。

### 1.2 1キャラから生成・加工する派生素材

- **戦闘用立ち絵（必須）**：マスターを主としてそのまま使用。可能な限り全身を表示、ただし現場のレイアウト制約では上半身中心も許容。武器や髪が不自然に切れないよう適切な包含領域を確保。背景透過。
- **HUD顔アイコン（必須）**：同じマスターの顔～肩付近を高品質に切り出す。正方形を基本（例：256×256、必要なら高DPI向け512×512）。人物の顔・髪型が判別でき、必要な余白を持たせる。別の顔を生成しない。
- **バストアップ（素材準備）**：同じマスターから頭～胸または腰上を切り出した透過素材。必要がない画面に無理に表示しない。例えば512×768など画像比率に合わせ、切り取りの自然さを優先。
- **追加の縮小版（任意）**：読み込み性能に必要なもののみ。拡大表示でぼけない品質を保つ。

元データを保持し、加工済みファイルを別名・別階層に保存。色・顔・衣装・装飾品・武器・ポーズは勝手に変更しない。元画像に焼き込み背景がある場合、背景除去は可能な範囲で行い、輪郭破綻や残存箇所を報告。破綻の大きい素材を黙って採用しない。

### 1.3 承認済み背景2枚

- `castle_corridor.png`：**道中（デッキ構築）**。朽ちた古城の長い石造りの回廊、突き当たりの扉、左右対称の正面構図。
- `castle_throne_room.png`：**ボス戦**。同じ古城の石材・色・柱の意匠を引き継いだ玉座の間、左右対称の正面構図。
- どちらも**人物・カード・HUD・文字などを背景に焼き込まない**独立アセット。ユーザー承認済みの画像をそのまま使い、必要に応じて軽量WebPなどに派生変換する。元画像は保存する。
- UIの視認性最優先。画像自体は描き込みがあるため、**控えめな暗色オーバーレイ・上/下部の局所グラデーション**で可読性を確保する。城の奥行きや玉座が完全に消えるほど暗くしない。
- PCは横長表示、スマホは主体を保つトリミング・背景位置調整。背景の繰り返し、画像伸長による歪み、道中/戦闘での取り違えを防止する。

## 2. 戦闘画面：全体構造

- ヘッダー、敵カード帯、戦闘フィールド、プレイヤーHUD、手札を、**継ぎ目のない1枚の玉座の間の背景**の上に重ねる。
- 個々の大きな背景パネル/枠線/グリッド境界線を撤去する。ただし**カード自身の枠・開閉メニュー・読みやすさのための薄いグラデーション**は残す。
- PC **1280×720の画面内に縦スクロールなし**で収める。1366×768も確認。
- ボス立ち絵はできるだけ大きく中央へ配置し、なるべく全身。実現困難な場合、全身を無理に収めず、上半身中心も許容する。敵カード/文字と重ならないようレイヤー調整。
- 背景の明るさやエリアサイズは、カード説明・操作ボタンが読めることを優先して微調整する。

## 3. 上部UI：左・中央・右

同じ高さ帯に3つの情報配置を行う。

**左上**（背景上の文字、パネル無し）
- `FIRST ERA · BATTLE DEMO`
- 大きく `TURN 01` など。
- `TURN` は**内部 `round` 番号の表示名だけ変更**。プレイヤー・敵が1回ずつ行動すると1増える。内部処理や戦闘ログのラウンド数え方を壊さない。

**中央上**
- ボスHPバーを画面**水平中央**、横長で配置。
- HPバーの**左上**＝ボス名。**右上**＝小さな現在HP/最大HP。
- HPバーの**左下**＝MPの菱形。最大3・残2なら `♦♦♢`。マナ上限3～5に従いアイコン数を可変にし、濃淡/形で使用可能と消費済みを区別する。MP数値を大きく表示しない。
- HPバーの**右下**＝バリア、毒、弱体等の**発生中のみ**の状態アイコン。数値は各アイコンの中または重ねる。補助効果の情報を落とさず詳細はツールチップ等で確認できるようにする。
- HPステータスを囲む独立パネル/太いボーダーは撤去。明瞭な文字影で可読性を確保。

**右上**
- **設定（歯車）と音量（スピーカー）アイコンの2つのみ**を小さく配置。
- **戦闘ログアイコンは右上に置かない**。設定メニューにも収納しない。
- 歯車を押すと右上付近に**小型設定メニュー**：演出速度（通常/高速）、最初から（実行確認あり）。
- 音量を押すと右上付近に**小型音量メニュー**：BGM・SEそれぞれON/OFFと音量スライダー。
- 両メニューは同時に開かず、画面外に出さない。既存の操作・音響仕様を保持する。

## 4. 敵デッキと戦闘ログ

- ボスHPバーの**すぐ下**に敵カード5枚を**常時横並び**。ボスMP/状態表示に干渉しない小余白を確保。
- カード名/コスト、使用済、基礎CD・残りCD等を最新の戦闘状態に追従させる。次のカード使用順や行動予定は予告しない。
- ログ開閉は**画面右端の縦中央付近に独立したタブを常設**。**絶対に右上の設定・音量と横並びにしない。**
- ログタブを押すと右端からドロワーを展開/収納。開いても戦闘進行は止めず、既存ログのスクロール方針は維持。

## 5. 下部：プレイヤーHUD／カード／操作

画面下部は**左から**、`プレイヤーHUD → 通常カード5枚（中央） → 継承専用枠 → 右下操作ボタン`。

**プレイヤーHUD**
- 画面左下に配置し、**手札カードの下端にHUD下端を厳密に揃える**。中間位置に浮かせない。
- 横幅は**220～250pxを目安（暫定）**。詰まる場合はカード幅/操作ボタン幅の調整を優先して画面内に収める。
- 左に小さな顔アイコン、右にボスと統一したHPバー構成：左上にプレイヤー名、右上HP値、左下MP菱形、右下に有効状態アイコン。
- HUDの外枠・背景パネルを撤去し、必要なら文字影・透明度の低い局所暗転で可読性を保つ。

**手札/継承枠**
- 通常手札5枚を画面下部中央に横並びで見せる。効果の短い要約が読めるようにする。
- 背景へ直接重ね、**手札背後のみ薄いグラデーション**。独立エリアの枠線は作らない。
- 継承専用枠は5枚の**右隣**、小余白を空けて置く。通常カードと高さを合わせ、横幅は**70～80%程度**。
- 第一紀では**暗い専用色の枠＋鍵アイコン＋「継承専用」「未解放」**の予約表示のみ。機能は追加しない。

**右下操作ボタン**
- **上：小さめ「マナ加速」／下：大きめ「ターン終了」**の2段。操作ボタン群も下部の自然な高さへ揃える。
- マナ加速は即実行、ターン終了の必要時確認は既存仕様に従う。

## 6. カードの詳細・使用演出

- プレイヤーカード選択時は元カードから**上方向**、敵カードは**下方向**へ約**1.5倍**で浮く（拡大率は仮）。
- **敵味方含めて拡大表示できるカードは1枚だけ**。以前の「敵味方各1枚同時拡大可能」は明示的に撤回済み。
- 別カード選択で対象を切り替える。元カードと周囲のカード列を押し動かさない。
- 拡大カードとボス立ち絵の重なりは許可し、拡大カードが手前。画面外はみ出しは禁止。
- 拡大カード周辺に**局所的な影・暗いハロー**を付ける。画面全体の暗転は不要。
- 敵ターン中はプレイヤーのカード使用もカードの新規拡大操作も不可。
- プレイヤーカードの拡大詳細に効果、コスト、使用条件、基本CD、残CD、**使用ボタン**を表示。敵カードには使用ボタンなし。使用後は使用済状態へ移行。
- 使用時はカードが元位置から**少し浮いて発光**→攻撃/防御/毒/回復等の効果演出→元位置へ。敵まで飛ぶアニメはしない。
- 演出中の次カード選択・詳細確認は許可するが、発動は演出終了までロック。CD・使用済などの表示は戦闘状態と一致させる。
- 予測ダメージをボスHPバー付近に表示する既存仕様を保持。防御・バリア・条件を適切に考慮。既存のターン切替演出（通常を旧実装から約0.5秒短縮）や高速演出を壊さない。

- UI背景を過度に明るくせず、文字とカードの視認性を保つ。PCでは回廊の奥の扉と左右対称構図がほどよく見え、スマホでは中央を基準にトリミング。

- スマホでは顔アイコンやHUD/カードの横幅を適切に可変化し、操作不能・カード切れ・意図しないはみ出しを作らない。

## 10. テストと受け入れ条件

1. **背景**：道中＝回廊、戦闘＝玉座。左右対称の意匠と違和感のない切り替え。画像にUIや人物が焼き込まれていない。
2. **素材**：6人分のマスターが正しく対応し、立ち絵・HUDアイコン・バストアップ素材が同一人物のマスターから加工されている。透過品質・頭/手/武器の欠損・顔アップの可読性を画像で点検。
3. **レイアウト**：PC1280×720で縦スクロールなし。1366×768でも文字、5枚の敵カードと味方手札、継承枠、ボタンが収まる。
4. **上段**：左上は `FIRST ERA · BATTLE DEMO / TURN`、中央HPバー、右上は**設定・音量だけ**。
5. **HP詳細**：ボス名左上/HP数値右上/MP左下/状態右下。プレイヤーHUDも同型で**手札の下端に揃う**。
6. **ログ**：右端の縦中央に**独立タブ**、右上に混入しない。開閉・閲覧で戦闘が停止しない。
7. **手札**：下部中央の通常5枚、右隣70～80%幅の鍵付き継承枠、右下は加速小＋終了大。
8. **拡大**：同時1枚まで、上下方向と拡大率約1.5倍、画面内制約、立ち絵重なり可。
9. **戦闘進行**：カード使用演出、CD/使用済、予測ダメージ、敵AIによる行動、毒・バリア・MPの処理など、前回デプロイ時の既存挙動を維持。
10. **スマホ**：上記3解像度でレイアウト崩れ・タップ不能・はみ出しなし。
11. **品質**：`npm test`、`npm run check`、`npm run test:browser` 等、リポジトリにある実行可能なテストを実施し、結果を報告。
12. **差分**：戦闘ルール・カード性能・AI・検証関連ファイルの非意図的な変更ゼロ。
