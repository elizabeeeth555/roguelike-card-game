## 更新のルール

- 採否 `confirmed / tentative / needs-decision / rejected` と同期状態 `pending / branch-ready / reflected / withdrawn` は別軸。曖昧な同意を勝手にconfirmedにしない。
- 重要な決定・保留・変更・撤回を節目で記録。一言ごとに更新しない。旧ID・条件・根拠を照合し重複を防ぐ。
- **メモMarkdownの保存・再取得→Issue索引更新・再取得**の順。単一ライター・直列更新。索引更新失敗時はメモから再構築。競合・未知IDなら停止。
- main正本（または事前承認された継続管理先）へ反映済みと確認したIDの節だけ削除し、索引から外す。Git履歴を維持。未マージでは消し込まない。
- 旧Issueコメントは移行前の履歴として残す。秘密情報は最初から保存しない。
