# 戦闘AI

## 本編：AI-2（確定／本編実装済）

[planner](../../src/game/boss-planner.js)は[共通戦闘コア](../../src/game/battle-engine.js)のコピーで合法な行動順を列挙する。MP・CD・条件・毒・消耗も同じ処理。
即時勝利手順を先に探す。通常は静的評価上位8候補を相手の応答と次の自ターンまで調べる。
その8候補を維持し、マナ加速を含む候補と《布石》を含む候補を、それぞれ異なる終了状態ごと最大2つ追加する。静的評価だけで準備手が落ちる問題への対策。
既存枠との同一行動列の追加を避けるが、全候補の終了状態をまとめるAI-Dではない。上位8＋最大4追加の構造であり、探索幅24ではない。
上位がすべて即敗北なら他候補の安全手も調査する。評価はHP、毒見込み、バリア、弱体、MP妨害、加速、布石等。タイブレークは固定。未来の非公開報酬や乱数を読まない。

## 採用しない研究方式

AI-D（終了状態全体の重複除去）、AI-L、幅24、反復状態での延長、評価関数全面変更は未採用。
AI-3の結果には重複除去と幅24が混ざるため、重複除去単独の効果と解釈しない。

## 研究モデルと限界

2ボスの合理モデルは本編AI-2そのものではなく、旗対象・構えを扱う有限探索モデル。[研究planner](../../research/two-boss/planner.js)の現在値は自手幅12・予算1800、候補上位4＋加速／布石各1、応答幅6・予算600、次自手幅4・予算300。新2スキル版は同じロジックを別エンジンへ接続する。数学的最適を保証しない。
雑モデルも合法手だが最適を狙わない比較操作であり、人間の下手さを定量的に再現するモデルではない。
新スキルの遅延利益の専用評価・候補確保が十分でない場合がある。スキルを追加すると旧有効手が探索から落ち、勝てた試合が負ける事例がある。
マナ加速の将来利益、防御と回復の周期、準備と即時火力の比較に限界がある。消耗で決着しても不自然な防御判断が解決したとは限らない。
有限探索で勝てないことは、適切な人間操作でも勝てない証明ではない。反実仮想の勝利手順も完全最適の証明ではない。

## 既知の問題・要確認

- 継承手当の2R周期停滞には、一手だけ変えると勝利できた事例がある。全戦闘を新AIで操作した結果とは別。
- 過去の即勝ち見逃し0件は監査標本内の結果であり、全盤面保証ではない。
- PC Node計測をスマートフォン実機速度と同一視しない。5枚ボスと6枚プレイヤーを分ける。
- 新スキルの遅延効果を正しく比較する追加研究は保留。本整理で再実験・AI改修は行わない。
