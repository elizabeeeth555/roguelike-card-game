# UI・操作・演出

## 現行の表示と操作（本編実装済）

スキル構築型ローグライクRPGとして表示を統一する。カード→スキル、獲得→習得、デッキ→スキルセット、継承カード→継承スキル。内部のcard/deckは互換性のため残す。
PCは中央ボス、公開敵5スキル、顔HUD、手札右の操作列、開閉式ログ。プレイヤー全身立ち絵は通常表示しない。
PCのプレイヤーHUD上端は手札上端へ揃え、下へ将来拡張可能にする。顔アイコンはPC50px・スマホ44pxを基準。スマホは敵→戦闘領域→自分の情報とスキルという縦導線。
右上は音量→設定。毒アイコンは紫、プレイヤーと敵の数字は読みやすくする。

### スキルパネル・詳細

- 左上：名前、右上：♦MP、中央：効果概要、右下：基本CD（0も表示）。分類は補助情報。
- 使用した所有者の自ターン中は「使用済」。終了後CDがあれば「CD中（残nT）」。排他表示とし、異なる色で区別する。
- 使用不可暗転でも文字を読める。MP不足・条件未達は既存合法判定に従う。
- 選択→詳細確認→使用の二段階。クリック／タップ詳細は効果全文とMP・基本CD・条件・使用不可理由を表示。閉じる操作を付け、PCでは別の読取専用ホバー／フォーカス詳細も表示。プレイヤーは使用ボタン、敵は使用ボタンなし。
- ダメージ予測の内部計算は残すが、長文の使用状態・予測・CD定義を効果文章へ混ぜない。
- 本体の位置を保ち、詳細枠だけ画面端で補正する。敵味方の左右端を中央へ大移動させない。通算1つの選択を基本とする。
- ターン終了時は合法なスキル／加速が残る場合に確認する。単なる余剰MPだけでは確認しない。

### 習得・交換・結果

通常習得画面にリロールとスキップ。詳細モーダルは名前・全文・閉じる・「このスキルを選択」。MP/CDは候補側で確認する。
交換候補は名前・MP・CD・概要、全文確認と交換確定を区別。取消は候補と分離した下部操作。交換中はリロール／スキップを隠す。取消で候補・残数・イベント進行を保持する。
勝敗後の操作不能理由は「戦闘終了」を「演出中」より優先。結果から再戦／最初からへ。古い継承画面を復活させない。
ログは開閉式ドロワー。閲覧中のスクロール位置へ配慮し、右上設定と干渉させない。

## 2026-11-10：第1弾実装と第2弾以降の方針

以下は最新のユーザー承認による採用仕様。上記「現行の表示と操作」は現時点の本編挙動を示すものであり、変更後の受入仕様ではない。2026-11-08実装値（敵スキル欄122px・効果概要の常時表示）や、過去のボス拡大方針より本節を優先する。第1弾は今回本編へ反映。第2弾以降は未実装のまま。

### 第1弾：PC戦闘レイアウトとスキル操作（確定／本編実装済）

| 項目 | 変更後の受入仕様 |
|---|---|
| PC全画面 | プレイヤー操作で全画面表示できるようにする。終了・通常表示へ戻る導線を設ける。 |
| 中央の戦闘領域 | 上部の敵スキル欄と下部のプレイヤーエリアを圧縮し、ボス・背景・FXのための中央領域を広げる。 |
| ボス立ち絵 | 現状より小さくする。縮小率・表示位置の具体値は実機調整で決める。以前の「大きくする」指示は置換。 |
| 敵スキル欄 | 公開された5スキルを維持し、通常時は**スキル名・消費MP・基本CD**を主要情報として簡潔に表示。効果概要は常時表示しない。「使用済」「CD中（残nT）」も判別できる。 |
| PCのスキル詳細 | **プレイヤー・敵双方**のスキルをマウスホバーだけで効果全文・条件等を確認できる。情報確認に選択クリックを要求しない。 |
| スマホのスキル詳細 | ホバーに依存せずタップで詳細を確認できる。確認操作で誤発動させない。 |
| スキル発動 | 既存の「スキル選択→『使用する』で確定」を維持する。複数の攻撃対象がいる場合は使用確定後に対象選択、単体ボスでは対象選択を省略。**複数対象選択UIは戦王統合時に実装**し、第1弾で戦闘ルールを変更しない。 |
| 非採用 | ドラッグ＆ドロップでのスキル発動は採用しない。ホバー時に直接『使用する』を出して選択クリックを省く案も現時点では**未採用**。 |
| 下部プレイヤーエリア | HP・MP・状態・スキル5枠と継承専用の未解放枠・マナ加速・ターン終了を維持したまま、縦幅を圧縮する。 |
| 操作性と可読性 | PCでは画面内完結（1366×768、1280×720を目安にスクロールなし）。文字・状態の視認性と押しやすさを損なわず、スマホでも表示崩れ・操作不能を起こさない。 |

クリック数を減らす対象は**情報確認**。発動は誤操作防止のため確定操作を残す。選択中のパネルや詳細が他のスキルを遮らず、詳細表示が画面外へはみ出さないこと。使用可否・MP・CDの判断は既存の戦闘コアに従う。
既存のターン終了確認、ログドロワー、ステータス表示、テンポ設定、演出スキップ、スマホ縦画面、勝敗・習得・交換UIを壊さない。実機の目視・操作確認を主な合否判断とし、既存自動テストも実施する。

### 第2弾：敵の行動演出とFX Lab（方向性確定／改修未実装）

- 敵スキル発動を **使用スキルの発光・点滅→敵キャラクターの行動→命中・ダメージ→毒・弱体など追加効果→余韻** の順に認識できるようにする。重複発動を防ぎ、次の行動を早すぎる間隔で流さない。具体的なミリ秒数は未確定で、現在の時間定義は既存実装の基準値。
- 演出中でも次のスキル効果の詳細確認は可能にするが、スキルの重複発動・確定操作は防ぐ。
- プレイヤーへの通常命中FXは左下の顔HUDではなく**画面中央下・手札付近**へ。老王《断誓一閃》などの大技は**画面中央を広く使う**。サイズ・座標・再生時間は実機とFX Labで調整する。敵の被弾数値と追加状態の論理順序は変更しない。
- FX LabはA/B比較を必須にせず、**単体の演出を直接編集する通常モード**を基本とする。比較モードは任意で残す。本編の新レイアウトとプレビューを同期し、既存の斬撃小・中・大JSONとレイヤー・SE設定の互換性を保つ。
- 本編のレイアウトが落ち着くまで、新しい演出JSONの量産は保留する。FX Labは別作業の[PR #1](https://github.com/elizabeeeth555/roguelike-card-game/pull/1)にあり、本PRは改変・マージしない。
- 敵そのものの固有能力・状態異常耐性は、PCホバー／スマホタップで確認する方向。戦旗のHP・再演予告など複数対象固有のUIはボス統合時に実装する。

## 最新の時間定義

[時間定義コード](../../src/app/presentation-timing.js)に一致する2026-11-08版。過去の約3秒、350ms等の宣言時間を置換する。これは演出設定であり戦闘ルールの時間ではない。

| 項目 | 通常ms | 高速ms |
|---|---:|---:|
| BATTLE START / YOUR / ENEMY / VICTORY / DEFEAT | 2000 | 1000 |
| フェードイン／維持／アウト | 300/1300/400 | 150/650/200 |
| 開始宣言→YOUR TURNの間 | 180 | 100 |
| ENEMY宣言終了→初動 | 700 | 350 |
| 敵行動開始→次の行動（演出を含む予算） | 900 | 550 |
| 決着→勝敗宣言 | 700 | 350 |
| 宣言後の結果フェード | 400 | 240 |
| プレイヤー通常／大ダメージ操作待機 | 420/700 | 280/420 |

BATTLE START完全終了→間→YOUR TURN。再戦も新戦闘として開始。YOUR青、ENEMY赤。常設ターン表示も高コントラスト。
宣言はクリック／Enter／Spaceで明示スキップ可能。敵行動は宣言完了後。敵行動予算と既存スキル待機を二重加算しない。

## FX・音声・可読性

タグと実結果から斬撃、毒、魔法、結界、回復、強化、マナを選ぶ。HPダメージ1〜2／3〜4／5以上で強弱を分け、バリア被弾・破壊をHP被弾と区別する。
ダメージは赤系「−数値」、回復は緑系「＋数値」、ハートなし。敵は上部、プレイヤーは下部に分ける。
追加状態の視覚演出は命中から約100ms遅らせる。論理計算順を遅延・変更しない。
論理処理と主要命中が終われば操作を戻し、残光の完全消滅を待たない。タスク世代で二重入力・リセット後の残留を防ぐ。
標準／軽量を保存。軽量は粒子と揺れを減らす。OSの動き軽減も尊重。HUDのレイアウトを揺らさない。
**2026-11-08時点の本編実装値（履歴）**：PC敵パネルは高さ122px基準（当時の旧44pxを置換）。スマホ5枚の名前12px・概要11〜12px、詳細15px基準。狭幅は省略し全文を詳細へ。**2026-11-10の最新承認により、PC敵パネルは再度圧縮し、通常表示は名前・MP・CD・使用状態のみへ変更済み。122pxは今後の受入基準ではない。**
BGM/SEのミュート・音量は維持。既存SEと自作12種、同音抑制・同時再生制限。5ボス別BGMの基盤はあるが追加4曲は未収録。権利・実ファイルは[素材](world-assets.md)。

## 敵スキル高さの設定化（STEP 2-B②・本編実装済）

対象は敵スキル欄のheightとmin-heightのみ。PCは70px、スマホは77pxを維持し、既存の760px以下／761px以上の境界も変更しない。設定と適用経路は[構造](../architecture.md#ui設定の最小適用経路step-2-b②)を参照。

今回の許容範囲はPC70〜78px、スマホ77〜85px（有限の数値、端を含む）。文字領域の縮小を禁止し、上部の固定フィールドと立ち絵領域の間に収まる小幅な増加だけを許可する。最大時の敵欄下端はPC188px／スマホ247pxで、立ち絵領域の上端216px／258pxより上にある。これは現在の配置を対象とした限定範囲であり、将来の汎用高さ編集範囲ではない。

PC・スマホを独立して適用し、無効値はそれぞれ70／77へ戻す。既定値の再適用で復帰でき、変数未設定時もCSSが既定表示を維持する。名前・MP・CD・使用状態、ホバー／タップ、二段階使用、下部UIの配置は変更しない。王座工房のUI／FX／Story編集や公開JSONスキーマ全体は未実装。

## React UIと王座工房での共通表示（2026-11-10最新承認）

**設計方針は確定、React版の実装は未着手**。本編UIをReact＋TypeScript＋Viteへ段階的に移行し、王座工房もReact製とする。スキルカード・HP／MP／CD・状態表示・パネル・モーダル等を共有可能なコンポーネントとして設計し、同じ表示設定・部品を本編の実データと工房の編集用データで使用する。既存の`presentation-config.js`／`presentation-adapter.js`によるPC70px／スマホ77pxの適用経路はPR #8でmain反映済み。移行時に数値・正常系を無断変更しない。

スキルの選択→使用確定、PCホバーの読取専用詳細、スマホタップ詳細、演出中の情報閲覧、ターン終了確認、ドロワー、習得・交換・結果UI、FX／SE時間・キャンセルの既存挙動を維持する。Reactに再描画を任せても、ゲームコアの合法判定と効果確定は唯一の真実とし、Reactが戦闘計算やエフェクトの完了条件を独自決定しない。旧版と並行比較し、PC 1280×720／1366×768、スマホ320〜430px、境界760／761px等で実測する。761px幅の長いCD状態表示の既存問題は別件として扱う。

将来のSteam向けPC配信を意識し、マウス・タッチ・キーボード、将来のゲームパッド操作、リサイズ・フルスクリーン・オフライン動作への拡張余地を残す。Steam発売・各専用機能の実装は未決定／未実装。王座工房でのUI配置・FX・Story編集も未実装。共通コンポーネントは描画を担当し、工房固有のドラッグ／編集イベントを本編UIへ混入させない。詳しい責務は[architecture](../architecture.md#react移行とsteam将来対応の設計方針2026-11-10承認)を参照。
