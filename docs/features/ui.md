# UI・操作・演出

## 最新方針と画面の適用範囲（2026-11-12）

新第一紀は[通常10種類から5つの自由編成](progression.md)・老王戦・別枠固定奥義・ローカル自動保存へ変更する。拠点／編成／戦闘を段階的にReactへ実装する。旧ランダム習得・交換・リロール・スキップの画面を無条件に移植しない。初期段階に解放ポイント・強化・試練のUIは作らない。

新進行のプレイヤーは通常5枠＋世代固有の固定奥義1枠を持つ。旧「継承専用1枠」は廃止で、今後のUI要件にしない。奥義は通常スキル・継承専用スキルとは区別する。個別の効果・名称・MP・配置の状態は[スキル正本](skills.md#first-era-ultimate)を参照する。[進行](progression.md)が編成確定・保存・確認付きやり直し・再戦の正本。

## 新第一紀・PC戦闘UIデザイン（2026-11-12承認／別入口に暫定実装）

**仕様状態：以下の「確定」に列挙した表示・操作の原則はユーザー承認済み。実装状態：第一紀プレイ可能版の別入口に暫定実装。透過立ち絵・採用音声は追加対応（専用ブランチ）。未登録絵・寸法/演出は調整対象。** 既存のclassic公開版と独立React技術検証画面は別の実装であり、第一紀画面はPR #26でmain反映済みだが、公開版への切替を意味しない。旧公開版の配置・サイズ・演出時間は下記の履歴節で保持し、新第一紀へ無条件に引き継がない。

デザイン基準は2026-11-12にチャットで最終承認されたPC戦闘画面の静止画（会話内成果物『灰鎖の老王との最終決戦.png』）。**画像の雰囲気と構図を基準**とし、画像内に描かれた仮のスキル名・HP・MP・CD・敵能力・装備等を正式なゲームデータとみなさない。画像のGitHub登録・実ファイル対応は未確認。1920×1080全画面を主なデザイン検討基準とするが、ピクセル単位の模写は受入条件としない。

### 1. 視覚言語と配色（確定／実装未反映）

- **重厚なダークファンタジー**。黒鉄・鈍い古金を基調に、石・革・煤けた銀を補助とする。装飾・金属の反射・常時発光・粒子が過剰なソーシャルゲーム風表現は避け、静止時は落ち着いた見た目、ホバーや発動時に強弱をつける。
- **クリック／操作できるスキルやボタンを主に装飾枠で示す**。ターン、キャラクター名、HP・MP・状態等の情報HUDは原則枠なし。HPゲージの極細輪郭、文字の影、背景の緩い暗色グラデーション、ログや詳細オーバーレイの可読性確保は例外として許容する。非操作情報に派手な金属額縁を設けない。
- スキル分類ごとのアクセント色：**攻撃＝くすんだ赤、防御＝鋼の青、毒＝暗い紫、強化＝鈍い金、回復＝落ち着いた緑、妨害＝灰紫**。カード全面をカテゴリ色で塗らず、アイコンや細線など部分的に使う。基調色は共通の暗色とする。
- ボス側スキル枠はプレイヤー側より**少し儀式的・装飾的**にするが、判読性と落ち着きを優先。使用可能／不可、選択、フォーカスは視認できる差を設ける。

### 2. PC全画面の基本配置（確定／実装未反映）

| 領域 | 承認された配置・表現 |
|---|---|
| 左上 | 英語でターン数と行動者（例：`1st Turn / Player`）。戦闘中のゲームロゴは常設しない |
| 上部中央 | ボス名と現在HP／最大HPを**同じ上段（名前が左、数値は右）**に配置、その下に赤いHPバー。さらに下の左にボスマナ結晶、右に状態アイコン |
| 中央 | ボス立ち絵を主役に、武器・顔・命中FXのための空間を残す |
| ボススキル | 横長5枚を**左3・右2**に浮かせる。ボスとパネルを背面の細く暗い鎖で接続する |
| 下部中央 | プレイヤーの**横長通常スキル5枚**を緩やかなアーチに配置。縦長のタロット型にしない |
| 奥義 | 通常5枠とは別に、アーチ中央直下へ**背が低く幅の広い横長盾型**ボタン |
| 左下 | 顔アイコンと**縦3段前後に圧縮した**プレイヤーHUD。スキルアーチの横に置き、横幅を無闇に広げない |
| 右下 | 見つけやすい「ターン終了」ボタン。右上に控えめな速度・設定操作 |
| 右端 | 通常は閉じている開閉式戦闘ログ。開いても戦闘画面をリフローさせない |

- ボススキルの**共通鎖**は全ボスで基本モチーフを統一。通常時は薄く、パネルは1～3px程度の目安でごく小さく揺れる（**振幅の数値は暫定・工房調整対象**）。操作の当たり判定は安定させる。ホバーは詳細閲覧のみとし、**実際の敵スキル発動時だけ対応する鎖を強調**する（2026-11-13承認で更新）。将来の**スキルパネル→鎖→ボス**への光移動は別途調整する。
- 顔アイコンは第一紀から表示してよい。敗北で人物が交代する演出は採用せず、同じ英雄が再挑戦する進行の正本は[progression](progression.md#敗北後の進行確定新進行は未実装)。

### 3. スキル・奥義のコンパクト表示（確定／実装未反映）

- **通常・敵スキル**：左に固有スキルアイコン、中央に技名、右上に**青いマナ結晶＋結晶の隣の消費数値**、右下に**砂時計＋右側のCD数値**。長い効果文を平常時の横長パネルに常時表示しない。`MP`・`CD`等の冗長な文字ラベルも基本表示しない。
- **奥義**：通常5枚とは独立した横長盾型。固有技イラストを背景レイヤーに敷き、その上に技名を重ね、右上の消費MP等は通常スキルと同じ表記規則にする。単なる汎用「奥義」ラベルより固有技名を優先する。奥義の個別効果・仮称・MP等は[skills](skills.md#first-era-ultimate)を唯一の正本とする。
- 通常／ホバー／押下／選択／使用可／MP不足／CD中／自ターン使用済み／条件未達／奥義使用済み等の**表示状態を区別**する。使用不可でも文字と詳細を閲覧できる。基本CDと残CDは砂時計の色や周辺状態で区別する（具体的な色・文言・アニメーションは調整対象）。

### 4. 詳細カード・ホバー・発動確認（確定／実装未反映）

- **縦長の同一詳細カード部品**をホバー・フォーカスとクリック後に共用する。上半分＝固有イラスト、下半分＝情報・説明。**技名は画像の下**、下半分上部に「技名＋MP結晶」、中央に効果全文・使用条件・必要な使用不可理由、右下に「砂時計＋CD数値」。
- **詳細カードのMP数値だけは大きい青い結晶の内側**に重ねる。通常パネルの「結晶の隣に数字」と使い分ける。CDは詳細でも砂時計の右に数字。
- PCでパネルをホバー・キーボードフォーカスすると同じカードを**小さく閲覧専用**で表示。左の敵スキルは左外側、右の敵スキルは右外側。奥義はボタンの**真上**に出し、他の通常スキルと一部重なってもよい。ホバーのみで実行・選択状態更新はしない。スマホはタップで詳細を閲覧できる。
- クリック時は**同じカードが中央へ移動・拡大**し、背景を控えめに暗転。プレイヤー側の中央詳細にはカードの下に「使用する」「キャンセル」。**「使用する」で初めて実行**する。敵スキルは読取専用で使用ボタンは付けない。閉じる操作、外側クリック、Esc等で解除できる。
- ログ開放時のレイヤー順は**中央詳細 > 半透明ログ > ホバー詳細 > 通常画面**。ログはホバー時にも自動的に閉じず、中央詳細はログより手前。カード間の一部重なりは許容するが、画面外はみ出し・誤発動は防ぐ。
- 奥義の再演対象など固有の補助情報は**効果説明欄**で扱う。第一紀の奥義専用カードレイアウトは作らず、同じ詳細カードを使用。個別の使用条件は[skills](skills.md#first-era-ultimate)へ集約。

### 5. HP・MP・状態・操作（確定／実装未反映）

- HPは**数値が主役**でバーは補助。双方とも`HP`ラベルなし。ボスは長めの赤バー、プレイヤーは**短い**バー。名前と現在HP／最大HPを一段目、バーを二段目に置く。表示は両者とも右側の数値が第一候補（確定した二段構造を維持）。
- プレイヤーHPバーは危険度の目安として**緑→黄／琥珀→赤**へ残HP割合で変わる。既出の境界例51–100%／26–50%／0–25%は**調整用目安**で固定閾値としない。数値は原則明るい文字色のまま。ボスバーは赤基調固定。
- MP HUDはプレイヤー・敵とも**最大MPの個数だけ結晶**を出し、点灯／消灯で残数を表す。`2/3`のような数値併記や、上限に関係なく常時5個を並べる表現はしない。
- プレイヤーHUDは顔の隣に**①名前・HP数値＋短いバー、②結晶＋マナ加速ボタン、③状態アイコン**をコンパクトに収める。状態アイコンの持続／蓄積など必要な数字だけ表示し、外側の装飾枠は付けない。
- **マナ加速のホバー**で翌自ターンの最大MP増加を示す淡い仮結晶を1個プレビューし、実行後は翌自ターンまで「予約中」の仮結晶を維持、次の自ターンに実際の結晶へ移る。既存の消費MP・上限等のルールは[combat](combat.md)を参照し、ここで再定義しない。上限到達時に不正な増加を予告しない。
- 右下のターン終了は使用可否・ホバー・押下・フォーカスを明確に。合法なスキル／加速が残るときの確認などの共通操作ルールは下記の既存節を維持。

## 第一紀・戦闘演出改善 第1弾（2026-11-13）

**仕様状態：今回の操作・表示方針は承認済み。実装状態：専用ブランチに実装・Chromium検証済み。main反映・公開は別途承認待ち。** 共通BattleViewを利用し、旧classicと独立React技術検証・工房の既存挙動を維持する。専用FX／SE・新素材の追加は行わない。

- 開始時は`BATTLE START`→`YOUR TURN`、交代時は`ENEMY TURN`／`YOUR TURN`、最終行動演出後は`VICTORY`／`DEFEAT`を表示する。宣言中は戦闘入力をロックし、詳細閲覧は可能。クリック・Enter／Space・演出スキップに対応する。宣言1枚の暫定時間はゆっくり2秒・通常1.2秒・高速0.5秒。既存の戦闘イベント順・計算結果・保存ログは変えず、スキップ／リセット後に古い宣言を再表示しない。決着宣言後は既存の戦闘BGM終了処理へ接続し、結果画面は無音を維持する。
- 使用可能なプレイヤー攻撃スキルの選択時、コアのsnapshotに対する読取専用transitionの攻撃イベントから、敵HPへのダメージとバリア吸収量を取得する。表示側にダメージ式を複製しない。敵HPバー上の予測減少範囲と、HP／バリアの別表示を暫定実装する。選択解除・発動・状態変更・操作ロック時に更新／消去する。最終的な予測アニメーション意匠は引き続き調整対象。
- 発光は使用者（敵／味方）とスキルIDの組で識別する。同じIDを双方が持っても実際の使用側だけを発光させる。
- 敵5パネルから老王への鎖を個別のSVG経路で描画する。実際の要素座標を測り、PC／スマホ・リサイズ・画像読込・発動中の動きに追従する。該当する敵スキルの発動時だけ1本を強調する。鎖は暫定描画で、素材化・共通部品の拡張は後工程。
- 通常待機時の中央メッセージは非表示とし、「スキルを選択してください」は表示しない。演出メッセージは必要な処理中だけ表示し、完了後に消去する。
- 老王の構え・崩しゲージは顔より上の位置へ移す。厳密な座標は暫定値で、PC／スマホ幅に応じて調整する。
- 設定モーダルの初期フォーカスはダイアログ本体とし、速度selectを自動選択しない。閉じると元の操作要素へフォーカスを戻す。Chromiumで初期フォーカスと明示的なselect操作を検証済み。**iOS実機のネイティブ選択UIは未確認**で、実機評価が必要。

## 現行の表示と操作（本編実装済）

スキル構築型ローグライクRPGとして表示を統一する。カード→スキル、獲得→習得、デッキ→スキルセット、継承カード→継承スキル。内部のcard/deckは互換性のため残す。
PCは中央ボス、公開敵5スキル、顔HUD、手札右の操作列、開閉式ログ。プレイヤー全身立ち絵は通常表示しない。
PCのプレイヤーHUD上端は手札上端へ揃え、下へ将来拡張可能にする。顔アイコンはPC50px・スマホ44pxを基準。スマホは敵→戦闘領域→自分の情報とスキルという縦導線。
右上は音量→設定。毒アイコンは紫、プレイヤーと敵の数字は読みやすくする。

### スキルパネル・詳細

- 左上：名前、右上：♦MP、中央：効果概要、右下：基本CD（0も表示）。分類は補助情報。
- 使用した所有者の自ターン中は「使用済」。終了後CDがあれば「CD中（残nT）」。排他表示とし、異なる色で区別する。
- 使用不可暗転でも文字を読める。MP不足・条件未達は既存合法判定に従う。
- 選択→詳細確認→使用の二段階。クリック／タップ詳細は効果全文とMP・基本CD・条件・使用不可理由を表示。閉じる操作を付け、PCでは別の読取専用ホバー／フォーカス詳細も表示。プレイヤーは使用ボタン、敵は使用ボタンなし。
- ダメージ予測の内部計算は残すが、長文の使用状態・予測・CD定義を効果文章へ混ぜない。
- 本体の位置を保ち、詳細枠だけ画面端で補正する。敵味方の左右端を中央へ大移動させない。通算1つの選択を基本とする。
- ターン終了時は合法なスキル／加速が残る場合に確認する。単なる余剰MPだけでは確認しない。

### 習得・交換・結果

通常習得画面にリロールとスキップ。詳細モーダルは名前・全文・閉じる・「このスキルを選択」。MP/CDは候補側で確認する。
交換候補は名前・MP・CD・概要、全文確認と交換確定を区別。取消は候補と分離した下部操作。交換中はリロール／スキップを隠す。取消で候補・残数・イベント進行を保持する。
勝敗後の操作不能理由は「戦闘終了」を「演出中」より優先。結果から再戦／最初からへ。古い継承画面を復活させない。
ログは開閉式ドロワー。閲覧中のスクロール位置へ配慮し、右上設定と干渉させない。

## FX・音声・可読性

タグと実結果から斬撃、毒、魔法、結界、回復、強化、マナを選ぶ。HPダメージ1〜2／3〜4／5以上で強弱を分け、バリア被弾・破壊をHP被弾と区別する。
ダメージは赤系「−数値」、回復は緑系「＋数値」、ハートなし。敵は上部、プレイヤーは下部に分ける。
追加状態の視覚演出は命中から約100ms遅らせる。論理計算順を遅延・変更しない。
論理処理と主要命中が終われば操作を戻し、残光の完全消滅を待たない。タスク世代で二重入力・リセット後の残留を防ぐ。
標準／軽量を保存。軽量は粒子と揺れを減らす。OSの動き軽減も尊重。HUDのレイアウトを揺らさない。
**2026-11-08時点の本編実装値（履歴）**：PC敵パネルは高さ122px基準（当時の旧44pxを置換）。スマホ5枚の名前12px・概要11〜12px、詳細15px基準。狭幅は省略し全文を詳細へ。**2026-11-10の最新承認により、PC敵パネルは再度圧縮し、通常表示は名前・MP・CD・使用状態のみへ変更済み。122pxは今後の受入基準ではない。**
BGM/SEのミュート・音量は維持。既存SEと自作12種、同音抑制・同時再生制限。5ボス別BGMの基盤はあるが追加4曲は未収録。権利・実ファイルは[素材](world-assets.md)。

- 詳細：縦長の同じ詳細部品をホバー閲覧/中央拡大に使用。プレイヤーは使用ボタンで確定し、敵は読取専用。演出中も閲覧可能、発動/終了は不可。MP/CD/状態/構え/崩し/再演元を明示し、威力と実HPダメージを区別する。
- 演出：コアの確定済みイベントを順番に表示する。強調→発動→ダメージ/バリア/回復→追加状態→余韻。敵は鎖・老王の動作を挟み、一手ずつ再生。一閃発動/阻止と崩しを明示。初期はゆっくり約4〜5秒/行動、通常/高速/スキップ対応。リセット後に古い非同期処理を反映しない。
- 勝利：第一紀踏破、タイトル/再戦。敗北：同じ英雄で拠点/再戦。第二紀は未実装の仮導線。素材原本は[素材台帳](../../assets/first-era/README.md)の指定4点を加工せず参照し、未登録絵は仮表示。専用FX/SEは本格制作しない。

寸法・装飾・演出時間は実機評価後に調整する暫定値。参考画像の仮の戦闘数値は採用せず、コアを正とする。

戦闘計算はコアで1アクション単位に確定し、返却されたイベントをログと表示用状態コピーへ順番に反映する。HP・MP・バリア・回復・状態・構え・崩しは各イベントに同期して段階的に表示し、アクション終了時にコアの確定snapshotへ同期する。表示側で戦闘計算・合法判定を再実装しない。演出スキップ時もイベント順序と初回勝利記録を保持し、演出中の詳細閲覧とスキル発動・ターン終了の操作ロックを分離する。

## 第一紀専用の音声（2026-11-13承認／専用ブランチ実装済み）

- タイトル・拠点・編成はForest Ambienceと焚き火を2レイヤーで継続する。画面切替・設定・詳細の開閉で最初から再生しない。
- 老王戦への切替は拠点音をフェードアウトし、Laments of the Warをフェードインする。戦闘中は再生位置を維持する。勝敗確定後も最後の戦闘演出が完了するまでは止めず、完了時点で老王曲を約1000msかけてフェードアウトする。フェード完了後に結果画面へ進み、結果は森林・焚き火を含め無音とする。再戦時は老王曲を先頭から再生し、タイトル／拠点への帰還では森林＋焚き火を再開する。全音源をループする。
- 最初のユーザー操作を音声開始の起点とし、操作前は音源を遅延ロードする。再生拒否やロード失敗はゲームを止めず、再試行を案内する。再生開始後の音源エラーでも内部再生状態を解除し、壊れた要素・音声ノードを破棄する。再試行は許可済みURLから新しく読み込み、古い再生／再開Promise・エラー通知は現在の要素・画面へ反映しない。
- 設定に全体ミュート、BGM音量、環境音量を用意する。初期値はBGM50%／環境音25%／ミュートなし、画面間フェード1200ms／戦闘終了フェード約1000ms（いずれも聴感評価前の暫定値）。このタブ内のみ保持し、ゲーム進行セーブ形式・工房保存・旧設定には書き込まない。
- 画面群ごとに再生管理を一本化し、各音源は最大1プレイヤー。通常のフェード区間だけ旧／新音を重ねる。バックグラウンドでは停止し、復帰時は再開を試みる。アンマウント時はタイマー・音声ノード・遅延再生を停止する。
- 第一紀ホストだけが音声管理を所有する。共通BattleView・工房・コアへ音声処理を混入させない。曲の交換は安定IDに対応するURLとVite許可リスト・素材台帳を更新する。

音源ファイル・出典・権利・加工履歴は[素材台帳](../../assets/first-era/README.md)を正本とする。Chromiumの再生／ループ確認は実機聴感やシームレス品質の確認とは別であり、実機でのバランス・継ぎ目・モバイルOSの音声復帰は要評価。
