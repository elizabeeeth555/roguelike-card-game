## 4. バージョン単位の作業の進め方

1. **このファイルで作業項目と対象範囲を選び、ユーザーと合意する。** 実装予定候補があるだけでは着手しない。
2. 作業前にGitコミットを作り、変更前の状態を再現可能にする。
3. Codexへ対象仕様・非変更範囲・受け入れ条件を渡す。Codexは関係ファイルを調査してから小さな差分で実装する。
4. `npm test`・`npm run check` と必要な手動テストを実行する。
5. デモをプレイして、**「面白いか」「操作の気持ちよさが上がったか」**を判断する。数値だけで採否を決めない。
6. 変更結果と決定事項を `docs/game-design.md` とこのロードマップに反映する。
7. コミット・プッシュし、GitHub Pagesの更新を確認する。
