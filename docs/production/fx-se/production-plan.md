# 『継世の王座』戦闘エフェクト・SE素材制作計画書

- 版：v0.1（2026-11-12／計画ドラフト）
- 対象：新第一紀プロトタイプの戦闘演出、および将来のスキル追加に備える共通素材ライブラリ
- 状態：**制作方法の基本方針は合意済み**。素材数・日程・サービス契約・詳細制作仕様は**提案／検証待ち**。
- GitHub変更：この資料作成のみ。リポジトリ、仕様正本、実装、公開版には未反映。

## 0. 目的と守る条件

### 目的
1. 斬撃・打撃・刺突・毒・防御・回復・魔法などの演出素材を、将来のスキル追加にも再利用できる形で揃える。
2. 人間の作業を「外部AIサービスへのプロンプト投入、出力の選別、最終評価・微調整」に限定し、素材加工・組み合わせ・タイミング配置・機械的検査はCodexに可能な限り委ねる。
3. 有料AIサービスを契約する前に、**生成→ダウンロード→背景処理→軽量化→実画面で再生→SE同期**を少数素材で実証する。
4. 有料契約する場合は、素材リストとプロンプトを事前に整え、原則1か月の集中生成で制作効率を高める。

### 既存仕様との境界
- 既存の戦闘処理、スキル効果・ID・MP・CD・条件・タグ、ダメージ／状態異常処理順を変更しない。
- 演出の共通原則：**通常技はテンポよく、強技・奥義・ボス大技は強めに**。ダークファンタジー基調、金属火花・煙・控えめな魔法光。ボスの踏み込みは少し拡大して下方向、被弾時は軽く後退。ヒットストップと揺れは技の重さに応じて差を付ける。
- **コード＋画像・アニメーション素材のハイブリッド方式**。動き・揺れ・同期はコード主体、複雑な視覚効果は必要に応じ外部素材を使用する。
- 王座工房は本編と同じ描画ソースを使用する。工房自体の編集機能の詳細は別セッションで検討し、本計画では決めない。
- `docs/features/skills.md`（個別スキル）、`docs/features/combat.md`（共通処理）、`docs/features/ui.md`（演出）、`docs/features/world-assets.md`（素材）、`docs/status.md`（進捗）を作業開始時に最新mainで確認する。本文中の技名や構成例は**正式なスキル定義ではない**。
- 未承認の研究・試作素材を確定仕様や公開版に自動昇格させない。非公開・購入素材はライセンス確認前に公開リポジトリへ登録しない。

| 状態異常 | 毒煙、呪い、暗紫粒子、弱体波紋 | 15 | A | 毒・妨害・デバフ |

| **計** | | **100** | | **動画100本ではない**。コード生成／静止画／動画／派生色違いを含む |

- SE：**50〜80種類**を初期目標案とする。武器の振り・命中・衝撃・鎖・防御・毒／魔法・回復・UI・余韻に分類し、強／中／弱や質感違いを用意する。
- 数量はあくまで仮置き。**優先Aの品質と再利用性を優先**し、無意味な色違い・似た音で水増ししない。
- 外部AI動画で作るべきものと、コード／SVGで十分なものをP0で分離する。**全100種を有料動画AIで生成しない**。

### 3.2 素材台帳の必須列
`asset_id / category / subcategory / description / source_type(AI-video,AI-image,code,licensed) / service / plan / generation_date / prompt_id / seed_or_settings / original_filename / processed_filename / dimensions / fps / duration_ms / alpha_method / hit_time_ms / loop / audio_peak / license_url / commercial_use_checked / redistribution_checked / storage_location / status / reviewer_notes`

### 3.3 命名と保存案（既存規約確認後に確定）
```text
private-assets/
  originals/video/       # AI生成原本、非公開
  originals/audio/
  processed/vfx/         # 透過・圧縮後
  processed/sfx/
  prompts/               # プロンプトと生成条件
  manifests/             # 素材台帳、ライセンス記録
  qa/                    # 比較画像・テスト結果
```
例：`vfx_slash_diagonal_01.webp`、`sfx_metal_impact_heavy_02.wav`。**正式な命名規則ではなく例**。

## 4. P1〜P3：契約前の具体的検証

### 4.1 アニメーション検証：斬撃（必須）
**準備物**：同じ内容の英語プロンプト、透過背景または単色背景の指定、生成条件の記録表、実画面の背景画像／検証画面、Codexの加工環境。

**生成プロンプト初稿（サービスに合わせて調整）**
> A single fast diagonal sword slash visual effect for a dark fantasy 2D RPG. A sharp curved silver-white blade trail with restrained antique-gold sparks, realistic metallic energy, strong readable silhouette. The effect appears, reaches its impact peak, and fades completely. Fixed camera, isolated effect only, centered on a uniform pure black background, no character, no weapon, no environment, no text, no logo, no watermark. Short, clean animation with no camera motion, no lingering particles at the beginning or end.

**検証手順**
1. ユーザー：候補サービスで同条件の素材を各1〜3本生成し、原本と設定を保存。
2. Codex：フレーム抽出、背景除去（単色キー／マスク／必要なら手法比較）、余白カット、透明縁の確認。
3. Codex：透過WebPまたはスプライトシート等に変換し、容量と画質を比較。動画形式が有利なら代替案も評価。
4. Codex：黒鉄・暗色背景上に重ね、スケール・角度・発動時刻を変えて再生。
5. ユーザー：輪郭、迫力、テンポ、違和感を評価。

**合格目標（暫定）**：背景残りや目立つ黒縁なし／発動から消失まで破綻なし／スマホ・PCで再生できる／命中時刻を後から変更できる／最適化後の容量と負荷を測定できる。容量・FPSの数値閾値は対象端末と画面実装を確認してP1で設定。

**失敗時**：単色背景→別色背景→静止画＋コードアニメーション→コード主体の斬撃に切替。**高額契約前に必ず代替ルートを実証**。

### 4.2 SE検証：金属衝突（必須）
**準備物**：同一プロンプト、試聴機器（スマホ・PC）、音量調整・波形確認環境、WAV等の原本。

**生成プロンプト初稿**
> A single heavy medieval steel sword impact against thick iron armor, close and punchy, sharp initial metallic clang followed by a short low resonant tail. Dark fantasy action game sound effect. Dry and focused, no speech, no music, no ambience, no repeated hits, no reverb wash. Clean isolated one-shot sound.

**検証手順**
1. ユーザー：ElevenLabs等で3〜5候補生成。商用利用条件を記録し、原本を保存。
2. Codex：無音カット、ピーク検出、音量整合、必要なら短いフェード、ブラウザ向け圧縮版を作成。
3. Codex：斬撃アニメーションの命中フレームにSEピークを合わせる。再生遅延と連打時の重なりを検証。
4. ユーザー：スマホスピーカー・イヤホン・PCで聴き、重さ／耳障りさ／繰り返し耐性を評価。

**合格目標（暫定）**：単発音として切り出せる／音割れなし／音量差が極端でない／アニメーションの命中に違和感なく同期／複数回再生で破綻しない。

**失敗時**：別プロンプト→複数短音の合成→権利確認済み既存SEへ切替。

## 6. P5〜P6：一括生成の実行ルール

### 6.1 プロンプトパックの構成
各素材に対して以下を1セットにする。
- 素材ID、用途、画面上の表示位置（プレイヤー／ボス／画面中央など）
- 正方向の英語プロンプト、除外したい要素（人物・背景・文字・ロゴ・カメラ移動など）
- 長さ、構図、背景色、色調、質感、動きの始点・ピーク・終点
- 推奨生成モデル／設定、採用判定ポイント、再生成時の調整文
- 生成日、サービス、プラン、実際の設定と採用番号

### 6.2 量産の優先順位
1. **A1**：物理斬撃・刺突・命中火花・金属SE・防御・毒（代表的な演出系統）。
2. **A2**：打撃・バリア破壊・回復・強弱差分・奥義の基礎パーツ。
3. **B**：炎・氷・雷・魔法陣・特殊な煙・環境SE。
4. **C**：未登場属性や用途が不明な演出。余力がある場合のみ。

**生成単位**：1プロンプトにつき少数候補を生成→採用率を記録→品質の良い型だけバッチ展開。採用済み素材の色替え・回転・速度変更で代替できるものは新規生成しない。

### 6.3 毎日の運用（集中生成期間）
- 開始前：残クレジット・今日の優先素材・保存先容量を確認。
- 生成時：ID付きプロンプトを投入、候補を保存、生成設定と消費クレジットを記録。
- 一次選別：採用／保留／破棄の3段階。採用理由・問題点を一言記録。
- Codex処理：加工・変換・テストをまとめて実施。失敗パターンを翌日のプロンプトに反映。
- 週次：採用率、未充足カテゴリ、費用消化率を確認。品質が低いカテゴリは制作方法を変更。

**契約期間の完了目標**：A群が全カテゴリをカバーし、再利用できる素材と生成条件が揃うこと。100種・SE50〜80種は**目標案であり納品保証ではない**。

## 7. P7：Codexによる自動加工・演出合成

### 7.1 自動処理パイプライン（提案）
`原本検査 → フレーム抽出／音声読込 → 背景除去・トリミング → 透明縁補正 → サイズ／長さ正規化 → Web向け圧縮 → メタデータ生成 → 画面内合成 → 自動テスト → レビューパック出力`

**素材形式**：原本は元形式のまま保存。Web実装向け形式は試験結果で決定。透過WebP／スプライトシート／SVG／Canvas／動画のいずれかを適材適所で使用。SEもWAV原本を保持し、ブラウザ向け圧縮版を別生成する。

### 7.2 タイミングの共通化
- **命中点を基準時刻 `impact_at_ms` とする**（技ごとの値は演出データ）。
- 発動／移動／エフェクト出現／命中／ヒットストップ／追加効果／余韻／SEピークを相対時刻で指定する。
- 戦闘ロジックから返る実際の結果に応じて、毒付与・バリア破壊などの条件付き演出を再生する。**演出が効果判定を変更しない**。
- 通常技は短め、奥義は強めという既存方針を維持し、具体的なミリ秒は試作後に調整する。
- SEの音量・同時発音数・連打時の抑制はブラウザ動作で検証する。

### 7.3 Codexの受入試験
- 素材が見つからない場合の代替表示とエラーログ
- 透過・再生時間・サイズ・ファイル参照の自動検査
- 代表3系統（物理攻撃、状態異常、防御）を実画面で確認
- PC・スマホの画面サイズ差、縮小表示、低負荷設定の確認
- 戦闘結果との同期と、スキルの効果・数値に変更がないことを検証
- 自動テスト、ブラウザ再生、ユーザー実機確認を別々に報告

**重要**：王座工房の独立した模倣画面を作らない。検証画面が必要なら本編と同じ描画コンポーネントを再利用する。工房機能そのものの追加は別途承認。

## 9. リスクと対応

| リスク | 兆候 | 対応 |
|---|---|---|
| 透過が不自然 | 黒縁・背景色の残留 | 背景色変更／マスク改善／コード主体へ切替 |
| 動画が長すぎる | 命中まで間延び | フレーム切出し・速度調整・短尺生成 |
| 生成が似通う | 同じ斬撃ばかり | 軌道・形・質感・強弱を軸に生成指示を変える |
| クレジット不足 | 試行回数増加 | A群優先、短尺化、静止画＋コードへ移行 |
| 素材が重い | スマホでフレーム落ち | 解像度／FPS／フレーム数／同時表示数の最適化 |
| SEが不自然 | 余韻が長い・音が軽い | プロンプト修正・音編集・複数音合成 |
| 権利が不明 | 規約が曖昧・更新された | 本編不採用、代替サービスへ切替 |
| 将来のスキルと不整合 | 専用素材に依存 | 共通部品＋プリセットを優先、追加ルールを残す |
| 契約の自動更新 | 更新日を失念 | 契約直後に更新日と解約手順を記録 |
