## 分類と優先度

- **画像**：画像生成・既存原画の加工が主体。
- **コード**：React/TypeScript、CSS、SVG、JSで生成・制御。
- **併用**：装飾画像とコードを合成。CSS/SVGで同等品質なら画像は省略可能。
- **P0** 共通部品・操作の検証、**P1** 第一紀の見た目、**P2** 演出・拡張、**P3** 後続画面。優先度は制作提案で、承認済みロードマップを上書きしない。

**UI-001以降のIDはこの台帳だけの制作管理番号。** スキルID・実ファイル名・コンポーネント名ではない。1項目が複数画像を含むことがある。

## 制作・管理ルール

1. **画像に文字・数値・技名を焼き込まない。** 変動する表示はゲームデータ＋Reactで描く。
2. **枠は9-slice／border-image／SVG**を優先し、角装飾を歪ませず伸縮させる。
3. 共通デザインは黒鉄・鈍い古金、操作可能な部品だけ装飾を強める。HUDは原則枠なし。分類色はUI正本を参照。
4. 透過素材はアルファと縁を確認。採用原画の同一性・ライセンスを確認し、購入・非公開原本はGitへ登録しない。既存の`/private-assets/`除外を尊重。
5. 画像・コード・併用の分類は**実装方式の提案**。王座工房で寸法・配色・表示時間を調整する。
6. PC 1920×1080に加えて1366×768、1280×720、スマホ縦画面で可読性・操作を検証する。
7. 実装済みの旧公開版・React技術検証・研究結果を新第一紀の完成とみなさない。素材の採用・本編実装・公開反映を別管理する。
8. FX/SEは既存制作マスターを参照。新たなボス能力・スキル仕様をこの資料で定義しない。
