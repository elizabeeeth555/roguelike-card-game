# 継世の戦闘 — ゲーム設計・仕様整理

**基準バージョン：Ver.0.9.5 / 更新日：2026-11-05**  
**目的：ChatGPTでの企画検討と、VS Code / Codexでの実装をつなぐ共通の仕様書。**

この文書は「ゲームとして目指す仕様」と「現在動くデモの仕様」を分けて記載する。**実装済みだから正式なバランスとして確定した、とは限らない。** 最新のユーザー承認がある場合はそれを優先する。

## 1. 企画コンセプト

### 1.1 目指す体験【方向性合意】

- シングルプレイヤーPvEのローグライクカードゲーム。雑魚戦を大量にこなすのでなく、**道中の短い選択イベントでビルドを作り、ボス戦に挑む**。
- 世代ごとに**別の英雄**が登場する。勝利した英雄の**通常デッキ**が次の時代のボスに引き継がれ、次のプレイヤーは前代の英雄と戦う。
- 勝利後、通常デッキから1枚を選んで次代へ託す**カード継承**がある。
- 目指す面白さは、カードの組み合わせ・準備・タイミングで大きな効果を生む爽快感と、「いま強くなるほど未来の敵を強くする」ジレンマ。
- **1枚への無制限な数値強化より、カード獲得・組み合わせ・ビルド変更を重視する。**
- 短時間で遊べるテンポ、読みやすい戦闘表示、PCとスマホでのテストプレイのしやすさを優先。

### 1.2 目標としないもの・未確定事項

- 現段階で複雑なストーリー、大量のマップ探索、マルチプレイは不要。
- 第四紀・第五紀、最終決戦、初代ボスの真の姿、過去の継承カードを取り戻す展開などは**将来の構想／検討案**。実装済み仕様ではない。
- 正式なデッキ枚数、HP、マナ上限、カード倍率、周回倍率、イベント出現率などの数値は**試作値**。

## 2. 現行デモのゲーム進行【Ver.0.9.5で実装済み】

1. 第一紀で初期ビルド（カード2枚）を選択。
2. 道中の選択イベントでカードを獲得し、最大5枚の通常デッキを組む。第一紀は強化不可。
3. 第一紀のボス「灰の騎士」を倒す。
4. 自分の**通常デッキ**から継承カード1枚を選択。前代の通常デッキを次代ボス用に保存。
5. 第二紀：新しいカードプール・初期ビルド＋継承専用枠の1枚で道中を進み、第一紀の英雄と戦う。
6. 第二紀に勝つと同様に1枚選んで第三紀へ。
7. 第三紀：さらに別のカードプールからデッキを組み、第二紀の英雄と戦う。勝てば**現行デモクリア**。

道中はテキスト選択中心。戦闘開始前に獲得・強化を終える。現行の通常デッキ上限は**5枚（仮）**、継承枠はその上限に**含めない**。上限に達していても獲得イベントは表示し、新カードと通常デッキの1枚を**入れ替える**か、新カードを**破棄**できる。

### 2.1 世代別の現行実装

| 項目 | 第一紀 | 第二紀 | 第三紀 |
|---|---|---|---|
| 対戦相手 | 灰の騎士 | 第一紀の英雄 | 第二紀の英雄 |
| 通常カードプール | 第一紀専用8種 | 第二紀専用8種 | 第三紀専用8種 |
| 初期通常デッキ | 2枚 | 2枚 | 2枚 |
| 通常強化 | 不可 | 1枚につき1回、強化（`+1`） | 1枚につき1回、強化・改（`+2`相当） |
| 固有ボス能力 | なし | 不屈の意志 | 闘争本能（仮） |
| プレイヤー最大HP | 42 | 52 | 62 |
| ボス最大HP | 45 | 59 | 72 |

HP・カード値は**Ver.0.9.5時点の実装値**であり、正式バランスではない。第二紀・第三紀のカードプールは互いに重複しない。切り札は通常カードプールとは別の獲得候補としても登場する。

## 3. 戦闘システム

### 3.1 基本【実装済み・基本方針合意】

- 固定手札方式。**ドロー・山札シャッフルなし**。デッキにある各カードを毎ターン選択できる。
- 先攻はプレイヤー、後攻はボス。通常、同一ターン内の各カードは**1回のみ使用可能**。カードのマナコストを支払う。
- **「切り札カード」**は通常デッキ内に入るカードで、別途**1戦闘1回**という制限を持つ（後述）。
- マナは概ねラウンドに応じ増加する。**敵の第1ラウンドのみ2マナ**、第2ラウンド以降は基本的にラウンド数に対応。プレイヤーは第1ラウンド1マナ。
- 戦闘にはHP・攻撃力・軽減（防壁／バリア）・毒・妨害などがある。
- **恒常的な「防御力」というステータスは存在しない。** 現行コードの「防御無視」は結界などの**ダメージ軽減を無視・貫通する**意味。表記改善は今後の調整対象。
- HPが0になった側が敗北。勝利時は演出後に継承画面へ。第三紀勝利でデモ終了。
- 敵AIは公開デッキからルールベースでカードを選ぶ。高度な学習AIは未実装。

### 3.2 代表的なカードと構築系統【カード名は実装済み・数値は仮】

| 時代 | 通常カード8種 | 得意分野の例 |
|---|---|---|
| 第一紀 | 斬撃、闘志、結界、返礼、穿撃、奮起、速攻、吸命 | 攻撃強化、防御・反撃、貫通、回復 |
| 第二紀 | 連牙、封魔、腐蝕、棘衣、血吸、破砕、堅陣、萎縮 | 連撃、マナ妨害、毒、攻防一体 |
| 第三紀 | 星火、破戒、残火、魔力脈動、癒しの詠唱、一騎討ち、雷閃、静寂 | 固定ダメージ、バリア破壊、毒、回復、妨害 |

正式なカードデータ・効果計算は `src/game/card-data.js`、`src/game/card-effects.js`、`src/game/battle-engine.js` を参照。**この表だけで数値仕様を上書きしないこと。**

### 3.3 毒と切り札【実装済み・数値は仮】

- 毒は再付与で**最大4層**まで蓄積し、持続ターンを更新する。継続ダメージは層数に応じる。
- 「劇毒開花」は**毒状態の相手にのみ使用できる、毒を消費する1戦闘1回の切り札**。毒を準備してから大ダメージに変換するコンボを試作中。
- 「逆境の一撃」も1戦闘1回の切り札。失ったHPに応じて強くなる。
- 切り札は**通常デッキの枚数枠を使用し、マナも消費する**。使用後はその戦闘中使用不可。次戦闘では回数をリセット。前代ボスの通常デッキに含まれていればボスも使用できる。
- **切り札カード ≠ 必殺技**。必殺技は別枠のアクティブ能力として検討されており、未実装。

### 3.4 ボス固有能力【Ver.0.9.5実装済み】

| 第二紀ボス | **不屈の意志**：プレイヤーターン開始時、バリア7を得る。残余はそのプレイヤーターン終了時に消滅。蓄積しない。 |
|---|---|
| 第三紀ボス | **闘争本能（仮）**：第2ラウンド以降、各敵ターン開始時に攻撃力+1（戦闘中累積）。 |

- **固定の周回固有能力**を持たせる方向性は合意済み。数値・能力の最終形はテスト結果次第。
- ボス固有能力は敵の「固有」アイコンから詳細を見られる。対策可能な能力とし、特定ビルドを完全封殺する効果は避けたい。

## 4. デッキ構築・カード強化

### 4.1 現行強化ルール【Ver.0.9.5実装済み】

- **第一紀は通常強化と刻印が不可**。
- **第二紀から強化可能**。同じ通常カードへの強化は、通常強化と特殊強化「刻印」を**合わせて1回まで**。
- 第三紀で「強化・改」に切り替わる。Ver.0.9.5では、二度強化するという意味ではなく、**1回の強化で上位グレード（レベル値2）を与える実装**。
- 強化済みカードは再選択不可。道中のカード詳細と「強化前→強化後」の表示、刻印の追加効果表示を維持する。
- 継承専用枠のカードは通常の強化イベントで選択不可。
- 未強化カードが残っていない場合、道中の強化関連イベントで進行不能にならないよう、カード獲得などに切り替える。

### 4.2 今後検討・追加する仕組み【未実装】

- **第四紀「強化・真」、第五紀「強化・覚醒」**：名称・段階の方向性は合意、具体効果と数値は未決。
- **継承専用カードの2段階目強化**：専用イベントで追加の成長機会を作る案。継承1枚への無限集中を避け、最大2段階という方向。ただし「元が未強化の場合」「適用グレード」「イベント回数」は未確定。
- **カード変異イベント**：任意の通常カードをランダムな別カードへ変異。**未強化のカードを選ぶと変異後は強化済みになる**案。強化済みの状態継続・カードプール・出現時代は未確定。独立した「カード交換イベント」は不採用。
- 道中のイベント配分は**カード獲得・ビルド構築を主軸**に調整する。

## 5. 継承と前代ボス

### 5.1 引き継ぎルール【ユーザー承認済み】

| 要素 | 次代ボスへ | 備考 |
|---|---|---|
| 前代の**通常デッキ** | **引き継ぐ** | 構成・各カードの強化段階・刻印等の付与効果を保持 |
| パッシブ能力 | **引き継ぐ** | 取得していた能力をそのまま（**未実装**） |
| 枷 | **引き継ぐ** | メリット・デメリットを含む（**未実装**） |
| 必殺技 | **引き継がない** | 切り札カードとは別概念（**未実装**） |
| 継承専用枠カード | **引き継がない** | 次代の英雄が使う別枠。前代ボスは通常デッキのスナップショットのみ |
| 周回固有能力 | **別途追加** | 前代の取得能力とは異なり、そのボス面に固定で付与 |

現在のデモでは**通常デッキの複製のみ実装**されている。パッシブ・枷のコピーは、対象機能そのものが未実装なので動かない。切り札カードは通常デッキのカードなので、ボスに継承される。

### 5.2 プレイヤーの継承カード【現行挙動】

- 各時代のボス撃破後、**その時代の通常デッキ**から1枚を選択する。強化状態は維持。
- 継承カードは次代の**専用1枠**に入る。通常デッキ5枚の枠外。
- Ver.0.9.5では前の時代から持ってきた継承カード自身を、再度の継承候補にすることはできない。次代を進むたびに、その時代の通常デッキから選び直す。
- 継承カードと同じ名前のカードを通常の獲得候補から除く実装がある。**変異による同名出現の禁止は変異機能を実装する際に整理すること。**
- 継承カードの**専用強化分**は通常デッキのスナップショットに混ぜない（専用強化自体は未実装）。

## 6. パッシブ・枷・必殺技【方向性・引き継ぎ規則は合意、機能は未実装】

| 種類 | ねらい | ボスへの引き継ぎ |
|---|---|---|
| **パッシブ** | 常時効果でビルドを個性化 | あり |
| **枷** | 自分へのデバフ、またはデメリットと引換えのメリット | あり（両面） |
| **必殺技** | 通常カードとは別枠で任意発動、原則1戦闘1回 | **なし** |

- 必殺技は専用枠で**1種類を装備する方向**。マナ消費なしは**仮案**であり、まだ確定していない。
- パッシブ・枷・必殺技の取得数・強さ・道中イベント頻度・実際のカードとの相互作用は未決。
- 画面に見えるアイコンは**実能力ではなくプレースホルダー**（ボスの周回固有能力のみ現行実装）。

## 7. 画面、演出、サウンド【現行デモ実装済み】

- PC横画面、スマホ縦画面のレスポンシブWeb UI。**敵情報は上、自分のHP・攻撃力・マナ・手札は下**。
- 敵カードを敵側に並べ、使用したカードを発光・テロップで示す。約2秒／カード（通常速度）。使用後は光を消す。
- `YOUR TURN` / `ENEMY TURN`：約3秒（フェード含む）。スキップ・高速表示あり。
- 攻撃・被弾・防御・回復などのSE、ダメージ表示、勝敗演出。勝利はヒット演出後に結果画面へ遷移。
- 戦闘ログは開閉でき、長くなっても画面全体が伸びない。スマホでは戦闘エリアと自分の情報の間に配置。
- パッシブ・枷・敵能力などの詳細はアイコンから**PCホバー／スマホタップ**で確認する方向。現行表示の一部は仮。
- 道中BGM：**Whispers in the Fog**、ボスBGM：**Determined Pursuit**。36種類の仮SE。BGM/SEのON/OFFと音量変更。
- 画像・音の参照は `assets/asset-map.js`。英雄・背景の仮素材は外部ファイルとして管理し、将来差し替える。英雄が次代ボスになっても同じ姿を表示。
- ユーザーは将来の正式素材を自分で調達・制作する方針。**仮グラフィックや仮SEを正式素材とみなさない。**

## 8. 技術・運用の方針

- 現行：HTML + CSS + JavaScript。大部分を `src/` に分割済み、`index.html` を直接開ける。
- BGM・画像は外部の `assets/` に分離。静的サイトとして**GitHub Pages**でテスト公開し、PC・スマホから同じURLでプレイする。
- VS Code + Codexでコードを編集し、GitHubへコミット・プッシュして更新する。
- React / TypeScript、クラウドセーブ、ランキング、サーバー／DBは**必要性が明確になってから採用を検討**。現時点で決定していない。
- `npm test` と `npm run check` は現行の検証コマンド。自動テストで全機能を網羅しているわけではない。

### 8.1 拡張に備えた構造整理【ユーザー承認済み／実装済み】

2026-11-05：ロードマップのバランス調整に先立ち、ゲームルールとブラウザ依存処理を分離。
カード効果・戦闘・強化・継承をNode.jsでも使える共通コアへ移し、画面・音声はイベント経由で適用する。
不変更新API、JSONスナップショット、解除可能な演出タスクを追加した。
カード性能・HP・AIの判断基準・継承規則を維持し、Reactやサーバーそのものは導入していない。
ファイル配置・利用API・移行時の責務は [architecture.md](architecture.md) を参照。

## 9. 既知のゲームデザイン課題【プレイから確認、改善策は未確定】

1. **大味・プレイヤー有利**：強い攻防一体カード、先攻確定、同じカードの毎ターン再使用、全体的に大きいダメージが主な疑い。敵初回2マナ・ボス固有能力をVer.0.9.5で試験導入。
2. **攻防一体の効率が高すぎる**：攻撃力を永続強化しながら防御・回復ができるカードが強い。専門カードとの差別化が必要。
3. **返礼／耐久型同士の停滞**：カウンター対カウンターの硬直を避け、軽減貫通や毒・妨害などの対抗策を検証する。
4. **毒の価値**：継続ダメージを主役にするだけでなく、毒を仕込んで「劇毒開花」などで大ダメージを出すコンボ（方向性B）を重視。
5. **ダメージインフレ**：現行は敵HPに対して通常ダメージが高い。通常攻撃倍率は控えめ、準備が必要な切り札・コンボは派手にする。
6. **周回インフレ**：HP・攻撃力などの表示規模を世代ごとに大きくする案（例：10倍刻み）があるが、**正式な倍率ではない**。プレイヤーと前代ボスを同一世代の基準で比較する設計が必要。
7. **ビルドの多様性**：アグロ・ミッドレンジ・コントロール・コンボ・テンポ等の系統に、機能する勝ち筋を持たせたい。

## 10. この文書の更新ルール

- バランス数値を調整しても、仮数値を正式決定に昇格させない。
- 大きな設計変更は `docs/roadmap.md` に作業単位で記録し、Codexが勝手に別仕様へ置き換えないようにする。
