# 第一紀・毒／再演奥義の独立研究

基点main：`b5ba25d6dfcd292bd08f5245b94b012c276c4074`。本フォルダの値は研究仮定であり、正式スキル定義・本編・工房・旧研究を変更しない。既存19種のData/Effects/Mathを読み取り、毒関連の新版だけ研究IDで差し替える。旧未追跡研究は実行依存に含めない。

## 実行

Node 24で依存追加なし。

```bash
node --test research/first-era-poison-replay/*.test.cjs
node research/first-era-poison-replay/run.cjs /tmp/poison-replay-main
node research/first-era-poison-replay/focus.cjs /tmp/poison-replay-focused /tmp/poison-replay-main
node research/first-era-poison-replay/confirm.cjs /tmp/poison-replay-confirmed /tmp/poison-replay-focused
node research/first-era-poison-replay/validate.cjs /tmp/poison-replay-validation
node research/first-era-poison-replay/probes.cjs /tmp/poison-replay-probes.json
node research/first-era-poison-replay/replay.cjs reports/first-era-poison-replay/focused/logs/ログ名.json
```

出力先が存在すれば停止する。過去結果を上書きせず、別の新規出力先を指定する。実測時間はマシン・JIT依存で、同じ数値を保証しない。シードと条件から行動列・勝敗を再現する。研究テストはrootの`npm test`から独立しており、両方実行する。

`run.cjs`は全20種の5枚組を列挙して分類し、一部を層別抽出→少数シード選抜→24シード詳細評価する。4つの10種候補プール内でも5枚組を列挙し、条件を満たす構成を試験する。最終候補はすべて再演奥義あり。奥義なしは補助的な感度分析のみ。

`confirm.cjs`は実際の毒寄与がある候補を追加確認し、`validate.cjs`は有望な毒刃設定と限定プールを24seedで再評価する。

`focus.cjs`は一次結果で「毒スキル入りだが実際は直接攻撃で勝つ」構成が上位を占めたことを受け、遅延毒を支える防御・回復構成を追加探索する。既存出力を変更せず、別フォルダへ保存する。毒評価係数と探索予算を変えた比較も分離する。

## 仮定

- HP双方20、通常5種・重複なし。初手MP2/上限3が主基準、MP3を補助比較。加速MP2・次自ターンから上限+1・最大5、CD、回復、強化／弱体、12R以降の消耗は共通コアの計算を利用。
- 老王の通常5種・構え・倍率・崩し・一閃は[ボス正本](../../docs/features/bosses.md)の暫定研究条件。初期不退、ボスターン開始で交互、崩した攻撃までは軽減。強化−弱体後・バリア前の値をゲージへ加え、構え倍率後に切捨て、最低1保証なし。一閃も強化・弱体とバリアを適用し、通常使用履歴へ加えない。消耗即死を最優先する。
- 新毒は残存ターン数、付与は加算、上限なし。対象ターン終了に固定2・バリア無視→残存1減少→毒死判定→相手バリア期限→次ターン開始。相手バリア期限を毒より前へ置く条件も比較する。正式順序ではない。
- 腐蝕／疫病の旧付与値2/3を、研究ではそれぞれ持続2/3ターンとして扱う。MP/CDは変えない。旧カウンターを新方式に正式移行したものではない。
- `r_poison_thrust`：毒突き、1MP/CD1、直接1。構え・バリアを適用後、実HPダメージが正なら1ターン付与。撃破で後続効果を止めるのは仮定。
- `r_venom_blade`：新版毒刃。基本1＋残存ターン/2。主基準はMP2/CD1・切捨て・毒消費0・対象の毒必須。これらの未確定値を4つのMP/CD組、切上げ、消費1、毒条件なし等で比較する。消費前／後の追加比較もある。主基準を正式承認済みと扱わない。
- `r_poison_release`：毒禍解放。主基準MP3/CD2。毒がある対象へ残存と同量の通常直接攻撃→全解除。構え・バリアを適用する。MP2/CD2は補助比較であり自動採用しない。
- 元の`venom_blade`／`heart_corrosion`は本番で改名・変更しない。研究プールは既存19−旧2＋新版3＝20。`r_`IDはこの研究だけの識別子。
- 再演奥義：同じ自ターンの最後の通常スキルを1戦1回だけ再演。独立枠でMP1／2を比較。元のMP/CD・使用済みを追加しない、条件を再チェックせず現在値で効果を再計算。加速を挟んでも参照し、自ターン終了で参照を破棄。奥義自体を再演元にしない。
- 強化・弱体は攻撃で消費するので元攻撃のボーナスを複製しない。強化スキルそのものを再演すれば現行の加算処理をもう一度行う。再演攻撃の通常攻撃履歴への記録は主基準ではあり、除外条件も比較。奥義履歴・元スキル履歴は区別する。
- 毒刃は使用直前の残存値で計算後に消費する主基準と、消費先行の補助条件を区別。毒禍解放の直後に奥義を使うと、毒0でも条件再チェックせず基本0を再計算する。旧ダメージを複製しない。空参照では奥義を使用不可とする仮定。
- 対象は老王1体のみで、複数対象・戦旗・継承・返礼／結界転化・奥義の永久保存は対象外。40R/400操作は研究安全上限。

## AI・指標・統計の制約

研究専用の有限ビーム＋相手1ターン応答探索。通常は幅10/予算450、上位4に加速／布石／奥義温存候補を確保、応答幅6/予算160。深い条件は幅18/予算1800、上位8、応答予算600。本番AI-2のままでは未実装ルールを扱えないため、その思想を参考にした独立モデルであり、同一AI・数学的最適解ではない。双方に同じ探索処理を使い、公開状態のみ参照する。

主評価はHP差×6、毒の将来価値は残存を最大6ターンで打ち切った線形項×2.3。毒係数6/9.6も別条件で比較し、長期毒の過小評価と探索幅の影響を調べる。通常モデルの敗北を人間の攻略不可能性と読み替えない。

老王・スキル効果に乱数はない。シード1〜24は同得点行動の選択だけに使用し、独立した24種類の遭遇ではない。勝率はこの方策・同点処理に対する記述統計であり、母集団勝率や精密な信頼区間を推定しない。同一行動列の数も記録する。選抜に使ったシードを詳細評価にも含むため、外部検証データではない。

`battles.csv`は各試行の条件ID、HP・ラウンド、直接／毒／解放／再演ダメージ、バリア・回復・MP・使用回数・崩し・一閃・AI時間等を保存。manifestでIDを実構成・条件へ対応付ける。`summary.json`は集計。`logs/`は実際の行動・イベント・HP/MP/CD等の推移を含み、replayで再検証できる。人工状態の相互作用プローブは実戦勝利と別物。

攻撃／防御等の使用分類はタグの重複を許す。奥義の直接ダメージは測定できるが、再演したバリア・強化・毒が後から生む利益は直接ダメージへ計上しない。奥義なし比較は再探索を伴い、固定手順の純粋因果効果とは異なる。崩し率の分母は初期と不退再設定の回数、一閃阻止率は実際の断誓移行時判定が分母。AI時間は両陣営のローカルNode計測。

結果・推奨・未解決事項は[検証レポート](../../reports/first-era-poison-replay/REPORT.md)を参照。今回の数値は仕様正本へ昇格させない。

## 保存結果の監査・レポート

成果物の再現時は、レポートルート配下に`data`（run）、`focused`（focus）、`confirmation`（confirm）、`validation`（validate）の新規出力を作る。各コマンドの引数で新規保存先と前段データを明示する。統計CSVの条件IDをmanifestへ照合する。`audit.cjs <新規レポートルート> audit-final.json`でCSV整合・全保存ログを再実行し、`pairs.py <新規レポートルート>`で対応する同一条件・シードの感度比較を行う（後者のみPython標準ライブラリが必要）。`report.cjs`はこれらの既定構成の結果から日本語レポートを生成する。いずれも出力済みファイルの自動上書きを拒否する。

`counterfactual.cjs <新規JSON>`はMP3での早撃ち失敗に対し、最初のプレイヤーターンだけMP2の記録手順を使い、その後双方を再探索する独立例。統計試行数に混ぜず1戦の反実仮想として数える。`probes.cjs`の7例は人工状態で、実戦7勝等の意味ではない。

初期オブジェクトの生成には既存コアを使うため、スナップショットの旧デモ由来プリセット・キャラクターIDは表示用の参照情報として残る。実際のボス通常スキルは老王の5種へ置換し、構え等は研究reducerだけが処理する。描画や本番セーブへこの研究スナップショットを渡さない。

CSVの`halfTurns`は実際の最終行動者から数えた経過行動フェーズ数。勝敗ラウンドと区別する。補正履歴はレポート側のmetric-note、現在のコード／入力ハッシュはprovenanceを参照する。

`representatives.cjs <新規レポートルート>`は保存済みログからターン別の抜粋を生成する。REPORT生成前に実行すると、概要と全行動JSONを行き来できる。

保存JSONは差分量を抑えるため集計1件／構成1件を1行へ整形している。再現対象は数値・データ構造・行動列であり、空白・改行や実測処理時間は含めない。
